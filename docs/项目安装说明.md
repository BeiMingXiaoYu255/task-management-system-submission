# 任务管理系统 · 安装与部署说明

> 版本：1.2.2　｜　适用平台：Windows（安装包）/ Linux / macOS（构建脚本 + CI）

## 1. 交付物与获取方式

> v1.1 新增：团队/子团队协作、跨团队任务双审核、AI 自动分配（本地规则引擎 + 可选 LLM）、站内通知中心。
> v1.0 安装版可直接覆盖升级到 v1.1，用户数据与数据库结构自动迁移（启动时幂等升级，不丢失数据）。

### 1.1 版本升级说明

> v1.2.1（源码版本）：修复桌面版便签小窗打开后应用卡死、无法关闭的问题（Tauri 窗口创建改异步 + 初始化路由修复 + 显式 Close 按钮）。

> v1.2.0（源码版本，本轮未重新打包）：界面已全英文（所有页面、提示、通知、错误均为英文），
> 默认技能标签/演示数据为英文。安装包仍为历史 v1.1.0，后续打包时一并发布。

> v1.1.1（源码版本，本轮未重新打包）：新增「系统设置 → AI 配置」页面，可在界面配置 LLM 并测试连通性，
> 无需再通过环境变量配置。安装包仍为 v1.1.0，后续打包时一并发布。
> 界面配置保存在数据库（system_settings 表），新表由应用启动时自动创建。
- **Windows 覆盖安装**：退出旧版本 → 运行 v1.1 安装包覆盖安装 → 启动，应用会自动完成数据库结构升级（新增协作/通知表与任务字段），
  旧账号、团队、任务数据全部保留；首次启动日志（%APPDATA%/TaskManagementSystem/logs/backend.log）可见"数据库结构升级完成/已是最新"。
- **LLM 配置（可选）**：默认使用本地规则引擎，无需配置即可用。启用大模型排序有两种方式：
  1. 推荐：登录全局管理员账号 →「设置 → AI 配置」填写 LLM Base URL、模型、API Key 与调度模式 → 保存，

  2. 环境变量：`llmBaseUrl`、`llmApiKey`、`llmModel`（可选 `llmChatPath`、`assignmentDispatchMode`），重启应用生效。
  界面保存的配置优先于环境变量；默认调度模式 `LOCAL_FIRST`：本地引擎无候选时自动尝试 LLM。

## 2. Windows 安装

### 2.1 系统要求
- Windows 10 1809+ / Windows 11（64 位）
- 需要 WebView2 运行时（Windows 11 已内置；Windows 10 若缺失，安装包会引导安装）
- 磁盘空间：安装后约 99MB；首次运行初始化数据目录约 150MB；内存建议 4GB+

### 2.2 安装步骤
1. 双击 `release/任务管理系统_1.2.2_x64-setup.exe`（30.9MB）；
2. 按向导完成安装（默认当前用户安装，无需管理员权限；默认创建桌面快捷方式）；
3. 首次启动时程序会自动完成初始化（约 10-30 秒）：
   - 在 `%APPDATA%\TaskManagementSystem\` 创建数据目录；
   - 初始化便携 MariaDB 数据目录（端口 3307）与 Redis（端口 6380）；
   - 启动后端服务（端口 8765）并创建默认数据库与账号；
4. 主窗口显示登录页即表示初始化完成。

### 2.3 默认账号
| 角色 | 用户名 | 密码 | 说明 |
| --- | --- | --- | --- |
| 超级用户（内置唯一） | `superAdmin` | `SuperAdmin@123` | 首次登录后请立即在"设置 → 修改密码"中修改 |
| 演示账号（可选） | `demoAdmin` / `developerA` / `designerB` / `testerC` | `Demo@123456` | 运行演示数据脚本后可用（安装版默认不含演示数据） |

> 安装版数据独立于开发环境；如需演示数据，可在安装目录执行：
> `resources\backend\runServer.exe` 同目录下无 Python 环境，不提供种子脚本；
> 可通过界面自行注册用户与创建团队（注册的新用户为普通用户，由超级用户/全局管理员在管理后台创建/认证团队）。
> 超级用户可直接在管理后台创建团队并提供给成员，或使用"创建团队"自助创建后由全局管理员认证。

### 2.4 局域网访问
1. 主机运行程序后，后端监听 `0.0.0.0:8765`；
2. 在"设置 → 局域网访问地址"或顶栏"局域网地址"按钮查看并复制真实地址（形如 `http://192.168.x.x:8765`）；
3. 同一局域网内的手机/电脑用浏览器访问该地址即可登录使用（同一套数据）；
4. Windows 首次启动若弹出防火墙提示，请勾选"专用网络"并允许访问；
   也可使用管理员 PowerShell 手动放行：
   ```powershell
   New-NetFirewallRule -DisplayName "任务管理系统" -Direction Inbound -Protocol TCP -LocalPort 8765 -Action Allow
   ```
5. 若主机 IP 变化，请重新查看局域网地址；路由器建议为主机配置固定 IP 或 DHCP 保留。

### 2.5 数据目录、备份与卸载
- 数据目录：`%APPDATA%\TaskManagementSystem\`（包含 MariaDB 数据、Redis 数据与运行配置）
- 备份：退出程序后复制整个数据目录；或使用 `mysqldump` 导出 `task_management` 数据库
- 恢复：将备份目录还原后启动程序
- 升级：直接覆盖安装新版本，数据目录保留
- 卸载：在 Windows"设置 → 应用"中卸载；**默认保留用户数据**；
  如需彻底重置，退出程序后手动删除 `%APPDATA%\TaskManagementSystem\`，下次启动将重新初始化

## 3. Linux 安装（构建产物）

### 3.1 构建
```bash
# 前置：Node.js 20+、Rust 1.80+、Python 3.11+、PyInstaller、系统 WebKitGTK 依赖
# Ubuntu 依赖安装示例：
sudo apt-get update
sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf \
  build-essential curl wget file libssl-dev libgtk-3-dev libayatana-appindicator3-dev

# 构建安装包（AppImage / deb）
./scripts/buildInstallers.sh
# 产物位于 release/ 目录
```

### 3.2 运行环境
Linux 桌面版运行需要本机可用的 MariaDB/MySQL（3307 端口）与 Redis（6380 端口），可使用：
```bash
sudo apt-get install -y mariadb-server redis-server
sudo systemctl enable --now mariadb redis-server
# 首次启动程序会提示/使用本地配置自动初始化数据库账号
```
> 也可直接使用第 6 节的服务器部署方式，用浏览器访问（无需桌面环境）。

## 5. 三平台 CI 构建（GitHub Actions）
仓库内置 `.github/workflows/build-installers.yml`，配置矩阵：
- `windows-latest` → NSIS 安装包
- `ubuntu-22.04` → AppImage / deb
- `macos-latest` → dmg
触发方式：推送 `v*` 标签或手动 `workflow_dispatch`。构建完成后在 Actions 页面下载三平台产物。

## 6. 源码 / 服务器部署（局域网服务端模式）

### 6.1 环境准备
- Python 3.11+、Node.js 20+
- MySQL 8+ 或 MariaDB 11+（创建 `task_management` 数据库）
- Redis 5+（可选，缺失时自动降级进程内存缓存）

### 6.2 安装与启动
```powershell
# 1. 后端依赖
cd Backend
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt

# 2. 配置数据库连接（复制模板后修改 databaseUrl/redisUrl）
Copy-Item .env.example .env

# 3. 构建前端
cd ../Frontend
npm install
npm run build

# 4. 启动服务（后端自动托管前端页面）
cd ../Backend
.\.venv\Scripts\python.exe -m uvicorn runServer:app --host 0.0.0.0 --port 8765
```
Linux/macOS 对应使用 `source .venv/bin/activate` 与 `python -m uvicorn ...`。
启动后：
- 本机访问：`http://127.0.0.1:8765`
- 局域网访问：`http://<服务器IP>:8765`
- 接口文档：`http://<服务器IP>:8765/api/docs`

### 6.3 以服务方式常驻（Windows 示例）
可使用 NSSM 或计划任务将 uvicorn 注册为后台服务；Linux 可使用 systemd：
```ini
# /etc/systemd/system/task-management.service
[Unit]
Description=Task Management System
After=network.target mariadb.service redis-server.service

[Service]
WorkingDirectory=/opt/task-management-system/Backend
ExecStart=/opt/task-management-system/Backend/.venv/bin/python -m uvicorn runServer:app --host 0.0.0.0 --port 8765
Restart=always

[Install]
WantedBy=multi-user.target
```

## 7. 常见问题排查

| 问题 | 排查方式 |
| --- | --- |
| 安装版启动后窗口报"后端启动超时" | 查看 `%APPDATA%\TaskManagementSystem\logs\` 下后端/数据库日志；检查 8765/3307/6380 端口是否被其他程序占用 |
| 浏览器访问局域网地址失败 | 确认主机防火墙放行 8765；确认设备处于同一网段；检查 `ipconfig` 获取的 IP 是否正确 |
| 数据库连接失败 | 检查 MySQL/MariaDB 是否启动、`.env` 中 databaseUrl 是否正确、数据库账号权限 |
| Redis 连接失败 | 系统仍可运行（自动降级内存缓存），日志会显示 `缓存模式：memory` |
| 忘记超级用户密码 | 停止服务，将 `superAdminUsername` 对应的用户数据删除/重置密码哈希，或重新初始化数据目录（会丢失数据，请先备份） |
| 端口冲突 | 修改 `.env` 中 port/数据库端口，或通过安装版自动选择 8765-8775 空闲端口 |
| 开发模式前端正常但局域网无法访问 | 需先 `npm run build`，由后端托管 dist；仅 dev server 时局域网需访问 5173 并额外配置后端 CORS |
