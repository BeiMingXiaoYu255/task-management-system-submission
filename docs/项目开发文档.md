## 1. 项目概述

### 1.1 项目定位
本项目是一款**轻量级桌面任务管理软件**，面向小型团队协作与软件开发场景。v1.1 新增跨团队/子团队协作与 AI 自动分配模块。目标是用尽可能小的体积与架构，
覆盖用户体系、团队协作、任务流转、待办清单、个人资料、系统设置、数据仪表盘与 AI 辅助（预留）等完整能力，
同时支持**桌面单机使用**与**局域网多人协同**两种形态。

### 1.2 核心指标
| 指标 | 目标 | 实现情况 |
| --- | --- | --- |
| 前端启动速度 | 构建后静态资源直接加载，无外部依赖 | Vite 构建产物由后端直接托管，首屏无第三方脚本 |
| 安装便捷 | 一个安装包完成部署，无需用户配置数据库 | Windows 安装包内置便携 MariaDB 与 Redis，首次启动自动初始化 |
| 局域网访问 | 同一局域网内任意设备浏览器访问 | 后端监听 0.0.0.0:8765，同时托管前端页面与 API |
| 界面风格 | 黑白极简、支持低饱和夜间模式 | 全灰阶设计令牌，浅色/深色双主题 |
| 代码组织 | 模块化、可复用、单文件 ≤300 行 | 前后端均按模块拆分，组件/服务/仓储分层 |

### 1.3 功能范围
1. **用户模块**：注册、登录、团队认证（团队创建审核）、全局权限分级（超级用户/全局管理员/普通用户）、
   团队权限分级（团队管理员/子管理员/自定义成员级别）、成员邀请/加入/踢出/转让、账号注销。
2. **任务管理模块**：发布任务（指定成员或级别范围、必须接受或选择性接受、优先级、截止日期）、
   个人待办自动生成、排序筛选、完成提交、发布者审核（通过归档/驳回重做）、任务状态机。
3. **个人资料模块**：个人简介、专长与技能标签、上级查看下级非隐私资料。
4. **系统设置模块**：主题、字号、字体、修改密码、注销账号。
5. **AI 辅助模块（预留）**：任务接收者推荐接口与前端交互（当前为启发式推荐，后续替换为大模型 provider）。
6. **仪表盘**：待办数量、一周完成数量、未完成数量、优先级/状态分布、团队维度统计（SVG 图表）。
7. **待办清单（便签模式）**：独立小窗口仅展示待办清单，支持快速操作。
8. **管理后台**：用户管理、团队认证、数据库表直接操作（含审计日志）、系统概览。

## 2. 技术选型

### 2.1 总体
| 层 | 技术 | 选型理由 |
| --- | --- | --- |
| 桌面壳 | Tauri 2（Rust + 系统 WebView） | 主程序体积约 10MB，内存占用远低于 Electron；可调用系统能力并编排后端进程 |
| 前端 | React 18 + TypeScript + Vite 5 + React Router 6 | 生态成熟、构建快、类型安全；不引入 UI 库/图表库，自研组件保证体积与风格统一 |
| 后端 | FastAPI + Python 3.11 + SQLAlchemy 2 + Pydantic 2 | 开发效率高、自动生成 OpenAPI、性能满足轻量场景 |
| 数据库 | MariaDB 11.x（MySQL 协议兼容，安装包内置便携版） | 规范要求 MySQL；便携版可随安装包分发，用户无需单独安装数据库服务 |
| 缓存 | Redis（便携版随安装包分发） | 登录限流、token 黑名单、统计缓存；Redis 不可用时降级进程内缓存保证可用 |
| 打包 | PyInstaller（后端）+ Tauri Bundler/NSIS（安装包） | 单文件/目录分发，安装体验好；Linux/macOS 通过 CI 构建 |

### 2.2 为什么前端不使用组件库
项目要求"黑白极简、代码可复用、体积最小"。自研设计系统（约 20 个通用组件 + 3 个 SVG 图表）
既能完全控制视觉风格，又能避免引入数千行第三方样式与运行时，符合项目目标。

## 3. 系统架构

### 3.1 桌面端运行拓扑
```
┌──────────────────────── Windows / macOS / Linux 桌面 ────────────────────────┐
│  Tauri 主程序（Rust）                                                        │
│   ├─ 系统 WebView 窗口 ── 加载内置前端静态资源（React SPA）                    │
│   ├─ 启动并监控后端进程：runServer.exe --manage-runtime                      │
│   │     ├─ 便携 MariaDB（127.0.0.1:3307，数据在 %APPDATA%/TaskManagementSystem）│
│   │     ├─ 便携 Redis  （127.0.0.1:6380）                                    │
│   │     └─ FastAPI + Uvicorn（0.0.0.0:8765，托管前端 dist 与 /api/v1）        │
│   └─ 关闭窗口时优雅结束后端及其子进程                                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 局域网协同拓扑
```
主机（运行桌面程序或服务端启动器）            局域网内其他设备
┌──────────────────────────┐            ┌────────────────────────────┐
│ FastAPI 0.0.0.0:8765     │◀── HTTP ───│ 浏览器访问 http://主机IP:8765 │
│  /           前端 SPA     │            │ 登录后即可协作（同一数据库）    │
│  /api/v1/**  REST API     │            └────────────────────────────┘
│  MariaDB、Redis（本机）    │
└──────────────────────────┘
```
- 前端与 API 同源，浏览器端无需额外跨域配置；Tauri 桌面窗口通过 `getApiBaseUrl` 命令获取本机 API 地址。
- 服务启动后可在"设置 → 局域网访问"中查看并复制真实访问地址。

## 4. 后端设计

### 4.1 分层职责（MVC 强化）
| 层 | 职责 | 约束 |
| --- | --- | --- |
| Controller 接口层 | 路由定义、请求参数校验、调用 Service、返回 Schema | 不写业务逻辑与 SQL |
| Service 业务层 | 权限校验、事务边界、状态机、组合多个 Repository | 可抛 AppException |
| Repository 数据层 | 封装 SQLAlchemy 查询 | 不含业务判断 |
| Model ORM | 表结构映射 | 字段 snake_case，属性 camelCase |
| Schema | 接口数据契约 | JSON camelCase，与 docs/development/apiContract.md 一致 |

### 4.2 数据模型（12 张表）
`users`、`teams`、`team_levels`、`team_members`、`team_join_requests`、`tasks`、`task_assignments`、
`task_reviews`、`skill_tags`、`user_skills`、`user_settings`、`audit_logs`。
完整字段与约束见 `docs/development/databaseContract.md`。

关键关系：
- 一个用户可加入多个团队（team_members 多对多中间表，携带团队角色与级别）。
- 一个团队自定义若干级别（level_order 越大级别越高），成员必须属于一个级别。
- 任务与执行人通过 task_assignments 一对多承载个人进度与审核意见；task_reviews 记录每次审核历史。

### 4.3 任务状态机
```
发布任务
 ├─ 必须接受 → 分配记录直接进入 进行中
 └─ 选择性接受 → 待接受 →（成员接受）进行中 /（成员拒绝）移除该分配
进行中 →（成员提交完成）→ 待审核
待审核 →（发布者通过）→ 已归档；全部执行人归档后任务归档
待审核 →（发布者驳回 + 意见）→ 重新进行中
未归档任务可被发布者/团队管理员取消
```

### 4.4 权限模型
1. **全局角色**：`superAdmin`（内置唯一，种子账号）> `globalAdmin`（由超级用户设置）> `user`。
   - 超级用户：设置全局管理员、全部管理后台能力、数据库直管。
   - 全局管理员：管理后台、团队认证、用户启禁、数据库直管。
2. **团队角色**：`admin`（唯一，可转让）> `subAdmin`（由管理员任命）> `member`。
3. **级别规则**：团队管理员自定义级别名称与等级数值；高级别成员可向低级别成员发布任务；
   只有管理员/子管理员可调整成员级别；子管理员只能管理级别低于自己的普通成员。
4. **审核规则**：任务默认由发布者审核；发布者注销后由团队管理员审核。
5. **团队认证**：新建团队为待认证状态，仅创建者可见；通过认证后才可邀请成员与发布任务。

### 4.5 认证与安全
- 密码：bcrypt（cost 12）单向哈希；注册/改密时校验强度（6-64 位且含字母数字）。
- 认证：JWT HS256，payload 含 userId、jti、过期时间（默认 7 天）；请求头 `Authorization: Bearer`。
- 注销：token 的 jti 写入 Redis 黑名单，剩余有效期内不可再用；修改密码后所有旧 token 失效。
- 登录限流：同一用户名+IP 5 分钟内最多 10 次失败，超限返回 429。
- 越权防护：所有团队/任务接口先校验成员关系与角色；权限判断集中在 `core/permissions.py`。
- 隐私：邮箱/手机号仅本人与全局管理员可见；查看他人资料需同团队且级别更高或具备管理权限。
- 数据库直管：仅允许单条 SELECT/INSERT/UPDATE/DELETE，禁止 DDL/多语句；全部操作写入审计日志。
- 审计日志：管理员关键操作与数据库直管操作留痕（操作人、动作、明细、IP、时间）。

### 4.6 错误处理
统一错误结构：`{ "code": "ERROR_CODE", "message": "中文提示", "details": null }`。
常见错误码：`INVALID_CREDENTIALS`、`TOKEN_EXPIRED`、`FORBIDDEN`、`NOT_FOUND`、`CONFLICT`、
`VALIDATION_ERROR`、`ACCOUNT_DISABLED`、`RATE_LIMITED`、`INTERNAL_ERROR`。

### 4.7 缓存与降级
- Redis 用途：登录失败计数、token 黑名单、仪表盘统计缓存。
- 启动时探测 Redis 可用性；不可用时自动降级为进程内内存缓存并记录状态（/health 返回 `memory`），
  保证单机场景仍可运行。

### 4.8 AI 辅助预留
- `core`/服务层提供 `aiService`，接口 `/teams/{teamId}/ai/recommend-assignees` 与 `/ai/status`。
- 当前 provider 为启发式实现：按级别范围过滤 → 技能标签与任务关键词匹配打分 → 输出中文推荐理由。
- 后续接入大模型时，新增 LLM provider 实现并替换 provider 配置即可，前端与接口契约不变。

## 5. 前端设计

### 5.1 设计语言
- 仅黑白灰阶；细边框、微圆角、无渐变、无阴影（弹层允许极淡阴影）；排版驱动层级。
- 浅色：白底黑字；深色：`#141414` 底、`#e8e8e8` 字，全部低饱和。
- 支持字号（小/中/大）与字体族（系统/无衬线/衬线/等宽）设置。
- 设计令牌集中在 `styles/tokens.css`，组件样式全部使用 CSS 变量与 CSS Modules。

### 5.2 路由
| 路径 | 页面 | 权限 |
| --- | --- | --- |
| /login、/register | 登录、注册 | 公开 |
| /dashboard | 仪表盘 | 登录 |
| /teams、/teams/:teamId | 团队列表、团队详情 | 登录/团队成员 |
| /teams/:teamId/tasks/:taskId | 任务详情 | 团队成员 |
| /tasks | 任务中心 | 登录 |
| /todos | 待办清单 | 登录 |
| /profile、/settings | 个人资料、系统设置 | 登录 |
| /admin | 管理后台 | 全局管理员/超级用户 |
| /sticky | 便签待办小窗 | 登录 |

### 5.3 状态管理
- `AuthContext`：当前用户与团队身份、登录/登出、团队角色判断。
- `ThemeContext`：主题/字号/字体，同步 html 根元素属性与 localStorage，登录后应用服务端设置。
- `ToastContext`：全局轻提示。
- 业务数据采用"页面局部状态 + API 调用"模式，不引入额外状态库，保持轻量。

### 5.4 请求层
- `api/httpClient.ts` 统一封装：注入 token、桌面/浏览器 API 基地址解析、错误转换（ApiError）、401 自动清理登录态。
- 各业务模块 api 文件与后端契约一一对应，类型定义在 `types/` 中集中维护。

## 6. 桌面端与打包

### 6.1 桌面进程编排
1. 用户启动 Tauri 主程序；Rust 读取资源目录下的后端可执行文件并启动
   `runServer.exe --manage-runtime --port 8765`；
2. 后端 `desktop/runtimeManager.py` 定位便携 MariaDB/Redis：
   - 首次运行在 `%APPDATA%/TaskManagementSystem/` 初始化数据库数据目录与随机密码配置；
   - 启动 mysqld（127.0.0.1:3307）与 redis-server（127.0.0.1:6380）；
   - 注入 `databaseUrl`、`redisUrl`、`jwtSecret` 等环境变量后启动 FastAPI；
   - 监控父进程 stdin，Tauri 退出时自动停止数据库、缓存与 Web 服务。
3. Rust 轮询 `/api/v1/health` 就绪后显示主窗口，超时显示错误提示；
4. 主窗口加载内置前端资源，通过 `getApiBaseUrl` 获取本机 API 地址；便签窗口通过 `openStickyWindow` 打开。

### 6.2 安装包形态与实测结果
| 平台 | 形态 | 说明 | 实测 |
| --- | --- | --- | --- |
| Windows | NSIS 安装包 `release/任务管理系统_1.0.0_x64-setup.exe`（32.4MB） | 内置便携 MariaDB、Redis、后端可执行文件与前端资源，开箱即用；安装到 `%LOCALAPPDATA%/任务管理系统` | ✅ 已实际安装、启动、登录、局域网访问验证通过 |
| Windows | 便携版 `release/TaskManagementSystem-portable-1.0.0.zip`（42.3MB） | 解压即可运行，无需安装 | ✅ 由同一构建产物打包含资源 |
| Windows | 主程序 `release/任务管理系统.exe`（9.2MB） | Tauri 桌面主程序（配合 resources 目录） | ✅ 安装版即基于该程序 |
| Linux | AppImage / deb（`scripts/buildInstallers.sh` + CI） | 系统安装 MariaDB/Redis 或使用 Docker 部署 | 构建脚本与 workflow 交付；需在 Linux/CI 上构建 |
| macOS | dmg（`scripts/buildInstallers.sh` + CI） | Homebrew 安装 MariaDB/Redis | 构建脚本与 workflow 交付；需在 macOS/CI 上构建 |

> 安装后占用磁盘约 99MB（backend 45.4MB + runtime 44.2MB + frontend 0.4MB + 主程序）；
> 首次启动初始化数据目录约 150MB（MariaDB 系统表 + Redis）。
> 开发机为 Windows，Linux/macOS 安装包无法在 Windows 本机真实构建，故交付可复现的构建脚本与
> GitHub Actions 三平台矩阵工作流（`.github/workflows/build-installers.yml`）。

### 6.3 端口与数据目录
| 项 | 默认值 | 冲突处理 |
| --- | --- | --- |
| HTTP API | 8765 | 启动时在 8765-8775 内探测空闲端口并回报前端 |
| MySQL/MariaDB | 3307 | 安装版固定使用 3307；被占用时由运行时管理器报错并提示 |
| Redis | 6380 | 同上 |
| 数据目录 | %APPDATA%/TaskManagementSystem | 卸载默认保留数据 |

## 7. 局域网访问
1. 主机启动应用后，设置为 0.0.0.0 监听；
2. 其他设备浏览器访问 `http://<主机局域网IP>:8765`，即可使用同一套系统（同一数据库）；
3. 应用内"设置 → 局域网访问"可查看并复制真实地址；
4. Windows 首次启动如弹出防火墙提示，需允许专用网络访问；安装说明中提供手动放行命令。

## 8. 本地开发指南

### 8.1 环境要求

## 10. 安全与数据

### 10.1 安全清单
- 密码 bcrypt 哈希存储，接口任何位置不返回密码哈希。
- JWT secret 由环境变量/安装时随机生成，不写入前端。

- 全部业务接口做服务端权限校验，不依赖前端隐藏按钮。
- 数据库直管接口仅管理员可用且限制为单条 DML，禁止 DDL 与多语句。
- 审计日志记录管理员敏感操作。
- 团队数据天然隔离：非成员无法访问团队、任务与成员信息。

### 10.2 数据备份与恢复
- 数据库数据目录：安装版在 `%APPDATA%/TaskManagementSystem/mysql`；

- 备份：停止应用后复制数据目录，或使用 `mysqldump` 导出 `task_management` 数据库。

- 升级：安装包覆盖安装保留用户数据目录；数据库表启动时自动补齐（create_all 幂等）。

### 10.3 卸载与重置
- 卸载程序默认保留 `%APPDATA%/TaskManagementSystem` 数据目录；
- 需要彻底重置时，退出应用后删除该目录即可（下次启动重新初始化数据库与超级用户）。

## 16. v1.2.1 便签小窗卡死问题修复

### 16.1 问题现象
桌面版点击顶栏「Sticky Notes」后，便签小窗打开但应用整体卡住（主窗口无响应），且便签窗无法关闭，只能强制结束进程。

### 16.2 根因
Tauri 同步命令（`#[tauri::command] pub fn openStickyWindow`）由 **主线程**执行；命令中同步调用 `WebviewWindowBuilder::build()`
创建新 WebView 窗口时，窗口创建需要事件循环参与，主线程在命令回调内等待事件循环 → **死锁**，导致应用界面冻结、窗口无法关闭。

### 16.3 修复内容
1. `openStickyWindow`、`closeCurrentWindow` 改为 `async fn` 命令，在 Tauri 异步运行时执行窗口创建，不再阻塞主线程；
2. 便签路由切换由「创建后 eval 脚本」改为 **`initialization_script`**（页面脚本执行前先把地址栏切到 `/sticky`，
   DOMContentLoaded/load 与定时器重试兜底），避免时序竞争导致小窗显示错误页面；
3. 便签页新增显式 **Close** 按钮；Esc 关闭逻辑修复（原实现把命令成功返回的 null 误判为失败再调用 `window.close()`）；
4. 窗口标题改为英文 `Sticky To-dos`，启动失败页与外壳提示同步英文化。
